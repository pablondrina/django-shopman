# constraints.txt — o que a imagem de produção instala, pinado.
#
# POR QUE ISTO EXISTE
# `pyproject.toml` declara FAIXAS (Django>=6.0,<6.1; requests>=2.31,<3.0). Sem um
# lock, o `pip install` do Dockerfile resolvia no dia do build: o que subia era o
# que o PyPI tinha naquela manhã, não o que a suíte tinha validado.
#
# Isso não era teoria. Na triagem de 2026-08-19, um deploy naquele momento teria
# instalado 40 pacotes diferentes do ambiente onde o `make test` roda — incluindo
# cryptography 46→50, Twisted 25→26, autobahn 25→26 e DRF 3.17→3.18. O
# `sentry-sdk` sequer existia no ambiente de teste, e ia para produção sem nunca
# ter sido exercitado.
#
# O Dependabot não pega isso: ele avalia a FAIXA declarada, então zero alerta
# nunca foi prova de que a imagem em execução estava limpa.
#
# COMO ESTES NÚMEROS FORAM ESCOLHIDOS
# Não são "o que estava instalado na máquina de alguém". É a resolução que o
# Dockerfile faria hoje, instalada num venv limpo e submetida à suíte inteira:
#
#     make test PYTHON=<venv>/bin/python   →   ✓ Todos os testes passaram
#
# 84 pacotes, que é o fecho de runtime — os 13 pacotes locais (shopman-*,
# django-shopman) não entram: instalam por caminho, versionados pelo próprio repo.
#
# COMO REGENERAR (depois de subir dependência, e só com a suíte verde)
#   python -m venv /tmp/v && /tmp/v/bin/pip install ./packages/* ".[dev]"
#   make test PYTHON=/tmp/v/bin/python                     # tem de ficar VERDE
#   /tmp/v/bin/python scripts/check_constraints.py --write # reescreve, cabeçalho incluso
#
# ⚠️ NÃO edite os pins à mão e não gere por `pip freeze`: o freeze despeja o venv
# inteiro (dev, ferramentas de teste), e o que interessa aqui é só o fecho de
# RUNTIME — o mesmo conjunto que o Dockerfile instala. O script resolve esse
# conjunto e é isso que o `make test-constraints` cobra no CI.
#
# ⚠️ Constraints CAPA versão, não instala pacote. A lista de dependências continua
# sendo o pyproject.toml; este arquivo só decide QUAL versão dentro da faixa. Foi
# exatamente por aí que o arquivo furou no dia em que nasceu: o `rapidfuzz` entrou
# como dependência nova, subiu SEM pin, e nada reclamou. Daí o guard.
